# 구조와 데이터 흐름

## 코드 배치

경로는 수정할 기능을 찾기 쉽도록 나눕니다. `app/`은 프레임워크 진입점, `components/`는 화면, `lib/`는 문제 데이터와 실행·채점 로직을 담당합니다.

| 경로                                   | 책임                                              |
| -------------------------------------- | ------------------------------------------------- |
| `app/page.tsx`                         | 인증 상태를 읽어 학습 화면에 전달                 |
| `app/api/training/`                    | CTF 제출, 개별 필기 연습, 노트와 완료 기록        |
| `app/api/exams/`                       | 모의고사 전체 채점과 응시 기록                    |
| `app/api/lab/`                         | 고정된 가상 문서 접근 제어 실습                   |
| `components/learning/`                 | 메뉴, 문제 목록, 검색·난이도 필터, 좌우 작업 화면 |
| `components/practice/`                 | 실행 Worker의 상태와 입력·결과 UI                 |
| `components/exams/`                    | 모의고사 답안, 타이머, 과목 이동과 오답 검토      |
| `components/editor/`, `lib/editor/`    | 입력 편집기와 구문 강조                           |
| `lib/content/`                         | 문제·이론·과목·난이도·내비게이션 데이터           |
| `lib/server/`                          | `server-only` 정답 키와 CTF 해설                  |
| `lib/runtime/`                         | 메모리 파일시스템, SQLite, 실행 Worker            |
| `lib/exams/`                           | 모의고사 구성, 선택지 검증과 점수 계산            |
| `lib/platform/`, `worker/`, `scripts/` | 호스팅 환경 및 개발 도구 연결                     |
| `db/`, `drizzle/`                      | 사용자 기록 스키마와 마이그레이션                 |

`lib/content/catalog.ts`는 학습 항목을 연결하는 얇은 집계 모듈입니다. 기사 개념·문제·실기, 모의해킹 시나리오는 각각의 파일에서 관리합니다. 정답 키는 공개 문제 데이터와 같은 폴더에 두지 않습니다.

`components/ui/`, `vendor/`의 외부 UI 원본과 라이선스는 보존합니다. 포맷 도구는 제품 코드와 문서에 적용하고 외부 원본·빌드 산출물에는 적용하지 않습니다.

## 실행 실습

1. 문제를 열면 Worker 안에 새 가상 Bash 또는 SQLite 환경을 만듭니다.
2. 입력한 코드를 Worker로 보내고 stdout·오류·테이블·파일 상태를 받습니다.
3. 리눅스는 기대 출력과 경로·파일 내용·권한을 비교합니다. SQL은 기준 쿼리 결과 또는 전체 테이블 상태를 비교하며 별칭이 다른 동등한 쿼리도 허용합니다.
4. 문제를 해결한 로그인 사용자의 완료 ID를 `/api/training`에 기록합니다.

실행 환경은 D1에 접근하지 않습니다. 실행 완료 여부는 개인 연습을 위한 클라이언트 채점이며 CTF 점수에 합산되지 않습니다. Worker 종료와 환경 초기화는 학습 기록을 지우지 않습니다.

## CTF와 모의고사

CTF는 서버의 정답 키와 제출한 flag를 비교합니다. 해결 기록은 사용자·문제 ID 조합으로 중복을 막습니다. 해설은 API 응답으로 전달합니다.

모의고사는 과목별 20문항, 전체 100문항입니다. 답안·현재 위치·다시 보기 표시는 계정과 회차로 구분한 브라우저 저장소에 임시 보관합니다. 전체 제출 시 서버가 채점하고 `exam_attempts`에 저장합니다. 같은 응시 ID를 재전송하면 처음 저장한 결과를 반환합니다.

학습 모드의 문항별 해설 확인은 개별 필기 연습 기록을 덮어쓰지 않습니다. 시험 모드는 전체 제출 이후 이론·해설을 표시합니다. 클라이언트 타이머이므로 감독 시험의 시간 통제로 취급하지 않습니다.

## 학습 기록

| 테이블          | 기록                                      |
| --------------- | ----------------------------------------- |
| `solves`        | CTF 해결 ID와 시각                        |
| `notes`         | 풀이·서술 답안·진단 보고서                |
| `checkpoints`   | 실행·개념·직접 검토 완료                  |
| `quiz_results`  | 개별 필기 연습의 마지막 선택·정오·횟수    |
| `exam_attempts` | 회차별 응시 방식·답안·시작·제출 시각      |
| `weeks`         | 이전 버전과 호환되는 공통 역량 체크리스트 |

기존 문제 ID를 바꾸면 기록 연결이 끊어집니다. 제목·분류나 파일 경로를 정리하더라도 ID는 유지합니다. `weeks`라는 테이블 이름은 호환을 위한 것으로 기간이나 주간 훈련 제약을 의미하지 않습니다.

## 콘텐츠 추가

- 실행 과제: `lib/content/practice/`에 문제와 실행 가능한 예시 답안을 추가하고 실제 상태 검증을 정의합니다.
- CTF: `lib/content/ctf/`의 문제, `lib/server/ctf/`의 정답·해설을 함께 추가합니다.
- 기사: `lib/content/exams/`의 문항과 `lib/server/exams/`의 정답을 연결합니다. 새 회차는 과목 배분과 문항 ID를 별도로 정의합니다.
- 모의해킹: `lib/content/pentest/`에 자료·범위·검토 기준·예시 답안을 두고 `public/labs/`에 다운로드 자료를 제공합니다.
- 난이도: CTF는 문제별 `level`, 실행·모의해킹은 `lib/content/difficulty.ts`의 분류 기준을 사용합니다.

변경 후 `npm run check`와 필요한 로컬 API 검사를 실행합니다. 신규 회차나 문항은 기존 제출 결과가 달라지지 않도록 ID와 채점 기준 변경을 검토합니다.

## HTML·CSS 코드 짜기

`lib/content/coding/`은 30과제와 요구사항·예시 코드를, `components/coding/`은 단계 선택과 편집·미리보기 화면을 담당합니다. `lib/coding/`에 단축키, 코드 저장, 문서 생성, DOM·스타일 검사를 분리했습니다.

작성 코드는 `codehack:coding:<viewer>:v1` 키에 즉시 저장합니다. 사이트 제작의 다음 단계는 기존 해당 단계 초안 → 직전 단계 초안 → 시작 코드 순으로 불러옵니다. 저장 실패는 화면에 표시하고 원본을 덮어쓰지 않습니다. 초기화는 해당 단계의 코드와 완료 기록만 지웁니다.

미리보기는 `allow-scripts`만 허용한 별도 iframe으로 실행합니다. 작성한 HTML에서 스크립트·이벤트 속성·문서 제어 요소를 제거하고, CSP nonce로 채점 코드만 실행합니다. `allow-same-origin`은 부여하지 않으며 외부 연결과 폼 전송을 차단합니다. 참고: [MDN iframe 보안 모델](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe).

검사는 960px와 390px 프레임에서 렌더링 후 수행합니다. 새 프레임의 레이아웃이 준비될 때까지 기다리고 5초 안에 응답이 없으면 재실행을 안내합니다. 결과 메시지는 프레임의 window·실행 토큰·요구사항을 검증하며, 코드가 변경된 이전 결과로 완료를 기록하지 않습니다. 완료는 기존 `/api/training`과 `checkpoints`를 사용하므로 새 DB 마이그레이션은 필요하지 않습니다.

Control + R은 코딩 작업 화면과 미리보기 안에서 실행하며 Command + R은 브라우저에 맡깁니다. 다운로드 문서에는 사용자 HTML·CSS와 연습 이미지가 포함되고 채점 스크립트는 포함되지 않습니다.
